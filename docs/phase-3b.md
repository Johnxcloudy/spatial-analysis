# Phase3B：查询生命周期与诊断可靠性

2026-09-10，用户授权继续下一步。沿用10–50万图斑、界面响应/计算有界、
数据保全与每阶段Git/执行说明要求。本轮目标0.6.2；公共协议/schema6、
worker5、readiness1不变，现有feat/phase-1a不强推。当前处于调查和实现中。

## 已核实的问题与未知项

- 原PR CI34441140400仍为Test engine失败，当前合法公开访问仅exit1，
  gh未登录，浏览器步骤日志要求登录。无法倒推原失败测试，更不能称偶发。
- 0.6.1原生分页helper有一次成功约3.998秒，但含query_unready等待/重发，
  原报告没有逐次计时，无法追认具体耗时层。Rust会串行持有引擎会话锁，
  测试工具直接native调用与产品JS队列可能在宿主汇合，需实际区分。
- 本轮独立假worker探针：3.5秒预热可使helper约3.8秒而实际操作约16ms，
  证明这是可能路径，不能证明旧事件原因。
- 假worker/延迟watchdog探针发现确定缺口：父进程收到成功帧时不再核对
  单调时钟截止，2秒操作可接受2.05秒响应；启动ProcessTreeJob失败时已创建
  的子进程未回收。证据仅在.artifacts/phase3b-query-probes.json，不归因于旧CI。

## 实施决定

1. 查询父进程按单调时钟核对原有截止，迟到成功按超时回收/重启，保留当前
   项目与分析任务；覆盖截止边界和下次恢复。启动任一步失败回收新子进程、
   资源监控、Job与管道。先建立确定性失败测试，不增加脆弱wallclock宽限。
2. 增加可关闭的本机宿主RPC计时：SPATIAL_TRACE_RPC=1时在既有有界desktop.log
   记录版本/请求ID/固定方法/队列、启动、交换、收尾、总时长及错误类别。
   不记录参数、路径、字段值、几何或响应；不改变公开RPC，默认不额外写日志。
3. 原生验收脚本拆分helper每次native尝试和就绪等待，记录有界UI/测试来源
   与时间轴，确保模拟错误独立于性能测量；只在真实数据副本与合成数据工作。
4. CI在原pytest命令旁保留JUnit，失败时仍生成有界、转义的公开测试摘要、
   实际checkout身份及诊断产物。保留测试原退出码和旧失败记录；新验证不能
   抹去旧失败或冒称读取了受限日志。

比较过的替代方案：直接提高时限会掩盖问题；在无分层证据时改宿主并发/缓存
会扩大一致性风险。先修复已复现的生命周期缺口并完善计时，以新证据判断
是否还需针对性优化。正式制图、Agent、分类补造和自动几何修复不在本轮。

## 验收

- 启动失败零泄漏、截止到期拒绝迟到帧、后续有效查询恢复；现有协议、取消、
  项目/快照保全与无效输入回归。
- 计时只写允许字段，默认关闭；成功/错误/排队路径语义正确，无用户数据。
- JUnit成功、失败、缺失、损坏以及特殊字符/超长内容均给真实有界结果，
  不因摘要脚本覆盖pytest退出码。
- 当前源码/冻结/原生50万分页、新时序报告、真实127面保全、适当全回归与
  NSIS/本机安装/卸载。不得把重用旧快照称为重跑完整50万分析或OS冷缓存。
- 推送并核对新CI实际checkout与结论，原PR不可知原因继续单列；更新执行
  说明/短交接/TODO。外部Windows、离线/升级、ArcGIS仍待条件。
