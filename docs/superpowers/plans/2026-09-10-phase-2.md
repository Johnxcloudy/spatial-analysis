# Phase 2 Implementation Plan

> For agentic workers: use subagent-driven-development with explicit ownership,
> focused tests, task review and final integration review. Continue authorized work.

Goal: deliver land clip/intersection statistics with a measured 500000-parcel
envelope and responsive, cancellable computation on the Windows desktop.

Architecture: immutable GPKG results contain geometry/statistics/provenance;
Python workers compute, a separate bounded process handles read queries, React
queues bounded view requests and native control traffic has deadlines.

Tech stack: existing Tauri/React/OpenLayers, Python/GDAL/PROJ/Shapely/PyArrow,
plus process monitoring. Exact domain and performance rules: docs/phase-2.md.

## Global constraints

Application 0.6.0, RPC/schema 6, worker 5. Existing feat/phase-1a branch; no force
push. Synthetic acceptance. Originals and prior results remain immutable. Use
apply_patch. shared/contracts.ts owns public types; root edits it before UI work.
500000 input/output records, 10000000 vertices, 100000 single-geometry vertices,
512 MiB snapshot, 5000000 analysis candidates, 10000 categories; analysis/import
worker 900 seconds/2 GiB, read queries 2 seconds/1 GiB. No silent simplification,
repair, overlap allocation, truncation of formal results, or invented progress.

## Task 2: capacity and bounded read queries (performance owner)

Files: vectors.py, vector_queries.py, new capacity.py/query_runner.py/
query_worker.py/resource_guard.py, corresponding tests; Rust engine.rs only.
No tasks.py/worker.py/rpc.py/__main__.py edits (provide adapters to root).

- [ ] Add failing streaming roundtrip/last-page/query deadline/worker guard
  regressions; preserve all existing Arrow attribute/geometry fidelity tests.
- [ ] Stream source batches into GPKG and compare batches without retaining
  the complete Arrow table. Centralize/enforce the capacity limits above.
- [ ] Bound SQLite scans and pre-transform geometry work. Implement reusable
  read-only query process with private validated messages, timeout, memory
  protection, respawn/warmup and no arbitrary operation execution.
- [ ] Provide a process watchdog independent of RPC polling, with measurable
  memory, monotonic deadline, specific termination reason and clean stop.
- [ ] Include mutex queue time in Rust deadline; avoid killing a healthy engine
  merely because a queued request expires. Root/UI controls queue priority.
- [ ] Run targeted existing/new Python and Rust tests; report integration API
  and evidence in .artifacts/phase2-performance-report.md.
