# Phase 3A：分页可靠性与真实数据首轮验收

2026-09-10，用户授权“开始下一步”，并提供仓库 `test/` 下的本地数据。
本轮目标应用 0.6.1；公共协议/schema 6、任务 worker 5、查询就绪协议 1
保持兼容。实现和本机源码/冻结/原生/安装验收完成，功能代码已推送；PR CI
在Test engine失败尚未闭环。详见[验证记录](verification-phase-3a.md)，不能
宣布远程全部通过或整个Phase3完成。

## 范围与设计

1. 优化无筛选的默认属性首/末页，保留数值内部 ID 顺序及真实总数。
   只有证明快照的内部 ID 与整数主键连续对应，才允许以主键范围直接寻址；
   不满足证明的旧数据、筛选或自定义排序保留正确的既有 SQL 路径。
   证明、查询和序列化仍受原有时限/内存保护，不修改登记后的快照。
2. 属性查询失败显示实际错误和“重试当前页”，不伪装成空表或零条记录。
   重试保留当前页、每页数量、筛选和排序，每次只发起一次；统计页复用
   显式刷新入口。项目/数据集/版本变化、隐藏或卸载后不重放旧请求。
   可恢复查询错误局部显示；引擎断连仍按现有重开项目流程处理。
3. 真实数据只读清点、完整导入、分页、显示查询、导出重读、另存与重开。
   原始文件集合和哈希在前后核对，用户数据与诊断产物留在忽略目录。
   不从文件名推断分类、单位、台账面积含义或无效几何处理政策。

本次数据只有127个面，不能替代10–50万压力验收。继续使用独立合成快照
测量分页速度、首轮初始化和新连接行为，不将新进程/新连接称为清空系统缓存。
保留1.5秒SQL、2秒查询、900秒任务预算；失败时记录原因和后续恢复。

查询方案比较：直接假定FID等于内部ID最快，但缺少旧快照证明；在已有快照
上添加索引会改变其字节和追溯身份。采用只读验证后优化，不能验证则回退。
首先采用无跨请求可信缓存的简单实现，避免仅凭mtime缓存结论、长持文件锁
或新增项目恢复状态；若实测需要改变此决定，须先记录证据和对应测试。

## 验收门槛与边界

- 解析样本验证1/2/10等数字排序、非连续/非规范ID、主键名冲突、旧快照、
  空表、NULL、重复排序值、筛选、末页与超响应预算；原始快照字节不变。
- 50万合成图斑的默认首/末页在原有查询预算下成功；报告原始与优化SQL
  分阶段时间、证明开销、p95和失败次数。保留旧失败，不放宽时限掩盖问题。
- UI测试验证失败和真实空表区分、显式重试参数不变、无自动循环、禁连点、
  新旧请求隔离、隐藏/切项目/断连行为；原生桌面使用真实后端验证分页。
- 用户数据验证依据字段、几何、来源FID、CRS和完整快照比较，不以显示效果
  代替保全；发现的数据质量问题保留并报告。未提供分类与第二层、存在无效
  几何时，不输出声称可用于业务的正式分类面积成果。
- 运行相关及完整回归、构建/冻结、发布版/本机安装检查并记录准确Git/CI。
  独立无开发环境Windows、真正离线/升级、ArcGIS软件对照仍单列待验收。
  Phase 3A完成不代表整个稳定版验收完成，正式制图和Agent仍为未来阶段。
