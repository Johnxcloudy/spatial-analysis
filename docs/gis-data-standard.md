# GIS 数据兼容与可靠性规范：优化草案

日期：2026-09-09

适用项目：Spatial Analysis Desktop。

状态：对用户第三份材料的优化草案，配合 [总体方案](plan-v2.md) 审阅。尚未通过实现和真实数据验收。

## 1. 目标与声明边界

系统必须正确读取支持范围内的数据，并清楚报告不能保留的内容。不能用“文件能打开”“地图看起来正常”代替属性、坐标、几何和统计的正确性验收。

兼容声明必须落实到格式、驱动和版本、几何类型、字段类型、元数据与读写方向。禁止承诺“任何常见 GIS 数据均可无损导入”，或以“接近 ArcGIS Pro”代替可测试标准。

原始数据不得被导入、投影转换和几何修复覆盖。未知信息必须记录为未知，不得补造 CRS、位置精度、字段含义或数据时间。

## 2. 统一模型与分类型能力

共同模型记录 id、名称、来源、来源版本或指纹、类型、范围、原始 CRS、字段描述、质量状态、处理历史及可用能力。

| 类型 | 附加信息 | 校验重点 | 可用范围 |
| --- | --- | --- | --- |
| VectorDataset | 几何类型、Z/M、稳定要素 ID、字段与分类信息 | CRS、单要素有效性、字段、按业务要求检查覆盖关系 | 仅通过工具输入要求后参与矢量分析 |
| RasterDataset | 波段、像元类型、尺寸、仿射变换、NoData、掩膜、分辨率 | 空间参考、波段语义、有效值、读取窗口 | 首版基础显示；后续按算法声明加入计算 |
| TableDataset | 工作表、字段、编码、坐标列及坐标来源 CRS | 类型、空值、坐标合法性、精度和单位 | 无坐标时仅为表格；成功建点后生成独立 VectorDataset |
| DisplaySource | URL、协议、服务 CRS、图层或瓦片矩阵及使用能力 | 连通性、服务声明和显示位置 | 默认显示；只有实际提供可读取要素时才另建分析数据 |

“统一”指对象和访问契约统一，不要求相同的物理存储，也不要求对所有类型运行 Polygon 校验器。业务模块通过数据服务访问受验证的对象，不能绕过导入和校验路径直接读取来源文件。

## 3. Phase 1 支持矩阵

| 输入 | 基础支持范围 | 明确边界 |
| --- | --- | --- |
| GeoPackage | 枚举和选择矢量层，读取普通几何和字段，保留 CRS，导出普通矢量 | 不自动宣称支持所有扩展或项目专有样式 |
| Shapefile | 读取组成文件、CRS、属性和编码；转换为托管矢量 | 缺失必要文件阻止导入；缺失 CRS 不能直接分析；已截断字段不能自动恢复 |
| GeoJSON | 按已声明的格式规范读取几何和属性 | 标准 GeoJSON 使用 WGS84 经度/纬度；历史非标准 CRS 文件必须明确处理，不能只改标签 |
| File Geodatabase | 通过 GDAL/OGR OpenFileGDB 枚举层、选择普通要素类、读取可支持的字段和元数据 | 产品首版只读来源；复杂语义按第 5 节报告，暂不承诺写回 GDB |
| CSV / Excel `.xlsx` | 选择工作表、X/Y 列、编码和来源 CRS；生成点数据 | 不把坐标统一猜成经纬度；旧 `.xls` 等未验证格式明确提示不支持 |
| GeoTIFF | 读取空间参考、波段、NoData、像元类型和分辨率，提供基础单波段或 RGB 显示 | DEM/遥感影像若使用其他容器，需按具体格式和驱动新增验收；不含栅格分析 |

SHP/GDB/GeoJSON 等普通矢量导出为 GeoPackage，并完成重新读取核对，是 Data Foundation 的验收项。用地分析结果与统计 CSV 的导出在 Phase 2 交付。

DWG/DXF、PostGIS、Enterprise Geodatabase、SuperMap、额外遥感容器及服务在实际接入时扩展支持矩阵。WMS/WMTS 的通用模型先明确，其完整适配不因出现在模型例子中自动成为 Phase 1 全部供应商的实现承诺。

## 4. 导入与校验流程

统一流程为：识别来源及能力 → 枚举内容 → 选择层/工作表/波段 → 解析元数据 → 校验 CRS 与字段 → 按类型校验数据 → 生成导入报告 → 转换或注册 → 校验目标 → 登记项目。

快速元数据检查与耗时的完整扫描分开执行，扫描进入 Task。尚未完成必要验证的数据只能处于检查中或受限状态，不得出现在正式分析的合格输入列表。

状态至少区分检查中、通过、带警告通过、阻止分析。报告记录已检查项、未检查项、发现数量、适用范围与校验器版本；抽样通过不能宣称整个数据集通过。

分析前重新检查输入版本、所需字段、CRS、单位、几何状态和工具前提。已完成且输入未变的完整校验可复用；来源、快照或策略发生变化时，相关校验失效。不能为了“每次检查”而无条件重复读取全部大文件。

## 5. GDB 与跨格式语义

File Geodatabase 是目录型数据库，必须通过成熟驱动访问，不解析或改写其内部文件。枚举时保留数据层和 Feature Dataset 的来源路径，避免不同命名空间的同名层被合并。

OpenFileGDB 的当前能力包括部分非线性几何、值域及关系等支持，不能把产品首版只读策略误写成驱动只能读取。实际可用能力以锁定版本、构建方式及 API 是否暴露为准。

| 信息 | 处理要求 |
| --- | --- |
| 字段名称、别名、原始类型、宽度/精度、空值约束、说明 | 驱动能够读取时保存在字段模型与元数据；缺失或未暴露时明确记录 |
| 编码值域、范围值域和子类型 | 保留原始代码及可取得的定义；不得只用显示名称覆盖代码 |
| 稳定身份 | 保留源 ObjectID/GlobalID 的映射，并生成内部稳定 ID；不以临时行号代替来源身份 |
| 关系、附件及其他专有规则 | 记录识别到的结构、导入范围和未保全部分；未检测不等于不存在 |
| 曲线与 Z/M | 明确分析链能否保留；需要线性化或降维时记录方法、容差与变化并保留来源 |
| ArcGIS 拓扑规则、网络等复杂行为 | 未实现时标记不支持，不把单要素有效性检查视作这些规则已通过 |

GeoPackage 可通过标准或扩展表达多种高级信息，但 GeoPandas/Shapely 或当前导出实现未必能够往返保全。以实际完成的转换测试声明兼容性，不把应用能力缺失归因于格式绝对不支持。

转换报告至少比较要素数量、几何类型、范围、CRS、字段映射、空值、ID、单位、已变更和未保全信息。需要修复或拆分时，逐项解释数量变化。无法证明全部保全时，不显示“无损转换成功”。

## 6. 坐标参考和转换

分别保存原始 CRS、显示 CRS、分析 CRS，使用完整 WKT 等可保存语义的表示，并保留适用的权威标识。EPSG 编号缺失不等于 CRS 不存在，有 EPSG 编号也不证明文件坐标正确。

识别只表示读取并解释声明。结合范围、轴顺序、单位和已知控制点检查合理性，不能根据坐标数值自动猜测后直接批准正式分析。

CGCS2000 经纬度坐标不是米制投影。面积等平面算法必须使用适用的分析投影，核对分带、中央经线和单位。采用测地算法时，应以独立工具及口径声明，而不是把角度单位当成米使用。

保存选用的转换操作、适用区域、可知的精度、格网资源和转换版本。缺少所需格网、转换不可用或质量达不到明确门槛时，阻止正式分析或要求选用合格方案，不静默退回低精度转换。

图层显示对齐不等于完成基准转换验证。中国商业地图使用的坐标偏移体系不能当作标准投影重投影问题处理；官方底图适配与分析数据的测绘 CRS 保持分离。

## 7. Geometry 与拓扑

导入自动检查适用的几何问题；单个 Polygon 有效，不代表整个地类覆盖无重叠、无缝隙。不同格式的环方向约定和重复节点问题也不能不加区分地当作必须修复的拓扑错误。

默认保留原始数据，生成修复副本与差异报告。报告包含修复策略、数量、几何类型、拆分/丢弃情况、面积变化和失败原因。可以按用户已经确定的策略自动处理；语义不确定、超过阈值或可能丢失数据时，需要在产品流程中明确采纳，不能静默覆盖。

“自动修复成功”只表示满足声明的检查，不保证恢复了真实地块边界。土地分类重叠的归属需要业务规则，不能按文件顺序或图层顺序自动决定。

## 8. 字段、编码与表格

字段模型保留名称、显示别名、来源类型、内部类型、长度/精度、单位、说明和映射规则。任何重命名、截断、类型变化或不支持字段都写入报告。

地类代码及标识符按其语义保存为字符串，保留前导零。超出 JavaScript 安全整数范围的 ID 以字符串或其他无损表示进入前端；不能因为地图能显示就忽略 ID 错配。

编码读取优先参考 CPG、驱动元数据和明确配置；支持经过验证的 UTF-8、GBK、GB18030。元数据冲突或检测不确定时提供预览与手动指定，并记录最终选择。不把替换字符当作正常中文静默接受。

CSV/XLSX 不凭前几行推断后就丢弃不匹配记录。坐标解析失败、空值或越界记录进入报告。公式坐标单元格需有可用值或明确值化，不把公式文本当坐标；选择工作表和坐标列的操作保存在处理历史中。

## 9. 精度、栅格和原生存储

分别记录位置精度、坐标存储精度、栅格像元分辨率和比例尺，附来源或未知状态。不能由“地籍”“道路”等名称推断精度，也不能将 10 米像元等同于 10 米位置精度。

栅格记录 CRS、地理变换、尺寸、像元类型、波段、NoData 和掩膜；NoData 不当作零。显示重采样与分析输入分离，分类栅格与连续数值栅格使用适合其含义的显示策略。

普通矢量默认进入托管 GeoPackage。大型栅格保留原生 GeoTIFF 或引用方式，按需建立缓存/金字塔；不因 GeoPackage 能存瓦片就将所有科学栅格强制变为有损图片瓦片。

项目保存原始路径、内部路径、相对路径、来源身份、转换报告和处理历史。原始文件不强制复制，但用于复现分析的输入版本必须可识别；托管矢量快照与外部原文件是不同概念。

## 10. 分级判定与验收

阻止项包括无法读取、分析 CRS 未确定、必要字段不存在、单位不合、相关几何检查未通过、来源版本变化尚未重新验证、目标格式无法保留算法必需信息。

警告项包括来源未提供位置精度、非必要别名缺失、已识别但不参与本次分析的高级元数据未保全。若任务设有强制精度门槛且无证据证明满足，则应升级为阻止项。警告和用户采取的处理政策写入分析记录。

验收至少覆盖：不同来源软件样本；GDB 多要素类与字段语义；中文编码；已知与未知 CRS；曲线/Z/M 处理；无效/重复/重叠面；坐标表异常；GeoTIFF NoData；导出重读；来源移动或变化；普通 Windows 离线环境。

需要跨软件验证时，对照 GDAL/QGIS 及可获得的 ArcGIS 导出样本。当前未获得 ArcGIS 实际环境或用户数据，不能宣称已通过 ArcGIS 互操作验收。

## 11. 官方依据

- [GDAL OpenFileGDB](https://gdal.org/en/stable/drivers/vector/openfilegdb.html)：驱动读写、几何及元数据能力。
- [GDAL GeoPackage](https://gdal.org/en/stable/drivers/vector/gpkg.html) 与 [OGC GeoPackage](https://www.geopackage.org/spec/)：标准与实现能力。
- [GeoPandas overlay](https://geopandas.org/en/stable/docs/reference/api/geopandas.overlay.html)：修复和几何类型行为。
- [GeoPandas area](https://geopandas.org/en/stable/docs/reference/api/geopandas.GeoSeries.area.html)：面积单位及平面计算。
- [PROJ FAQ](https://proj.org/en/stable/faq.html) 与 [projinfo](https://proj.org/en/stable/apps/projinfo.html)：CRS、资源和转换选择。

实现必须以锁定依赖和测试数据的结果为准，不能仅引用驱动文档就宣称整个应用完成兼容。
