## 冷读查询限制与优先后续工作

只读 `EXPLAIN QUERY PLAN` 显示默认首/末页执行 `SCAN features` 和
`USE TEMP B-TREE FOR ORDER BY`。内部 `_sa_id` 为文本，按数值
`CAST(_sa_id AS INTEGER)` 排序不能直接使用 `_sa_fid` 整数主键排序；
`COUNT(*)` 另行扫描。SQL 共用 1.5 秒截止时间，外层查询子进程预算 2 秒。
冷 IO 或并发负载会增加触发限时的风险，但查询计划本身不能确定上述实际
超时发生在哪一条 SQL。本轮保留限时与失败证据，最终新运行成功。

证据：`.artifacts/phase2-attribute-query-plan.json` 和
`.artifacts/phase2-attribute-query-diagnosis.md`。下一阶段优先验证稳定排序键/
索引、显式重试交互及冷读验收。不能直接去掉 CAST 改成字典序；使用 FID
前须验证所有导入/分析/历史 schema 的 ID 顺序不变量。本阶段没有为通过验收
改动查询生产代码，也未交付自动重试。受控超时保留项目，不等于 UI 或计算死锁。
